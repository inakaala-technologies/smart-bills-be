# API Versioning

## Base path
- /api/v1

## Principles
- version from the start
- keep backward compatibility through versioning
- use consistent resource naming
- separate domain routes by capability

## Example routes
- /api/v1/auth
- /api/v1/businesses
- /api/v1/customers
- /api/v1/billing/invoices
- /api/v1/payments
